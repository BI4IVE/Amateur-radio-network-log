# 微信推送功能说明（v2.0.0）

> 适用版本：v2.0.0 及以上
> 功能目标：用户在公众号绑定自己的呼号后，主控台每提交一条该呼号的参与记录，
> 该用户的微信就自动收到一条「台网参与回执」（模板消息，**用户免交互**，类似银行消费通知）。

---

## 一、功能原理

```
用户绑定（公众号 H5）          主控台提交记录              微信收到回执
   呼号 ──绑定──▶ openid   →   记录落库 → 查绑定 → 推模板消息  →  用户微信
```

- **触发时机**：主控台提交记录并落库后异步推送（不阻塞提交，失败不影响记录保存）
- **推送对象**：只推给「呼号一致 且 绑定状态为已生效」的微信用户
- **推送内容**：呼号 / QTH / 设备 / 天馈 / 信号报告 / 时间（字段可后台配置）
- **三种绑定方式**：身份证后六位、一次性绑定码、人工审核（管理员后台选择，见第六节）

---

## 二、硬性前提条件（不满足则整条链路不通）

| 条件 | 要求 | 为什么 |
|------|------|--------|
| **公众号类型** | **认证服务号**（企业/组织主体 + 已完成微信认证） | 模板消息是认证服务号的能力；个人订阅号、未认证订阅号**没有**此权限 |
| **模板消息权限** | 已开通「模板消息」功能插件 | 这是推送通道本身 |
| **域名** | 已完成 **ICP 备案**，站点支持 HTTPS | 微信网页授权域名强制要求备案；回调地址要求 HTTPS |
| **服务器** | 公网可访问（443 端口开放） | 接收微信回调、提供 H5 绑定页 |

> ⚠️ 个人订阅号或未认证公众号**无法**使用本功能。如不满足，需先升级为认证服务号。
>
> 微信后台菜单名称会随版本调整，以下路径找不到时，请使用后台右上角的**搜索框**搜索关键词（如「模板消息」「服务器配置」）。

## 三、公众号侧配置（6 步）

### 步骤 1：确认公众号类型与认证状态

路径：**设置与开发 → 公众号设置 → 账号详情 / 认证情况**

- 账号类型应为「服务号」
- 认证状态应为「已微信认证」

### 步骤 2：开通模板消息功能

路径：**功能 → 添加功能插件 → 模板消息**（或后台搜索「模板消息」）

- 点击申请开通，认证服务号一般即时通过
- 通过后可见：模板库、我的模板、日调用上限（通常 10 万次/天）

### 步骤 3：选用模板，拿到「模板 ID」和「keyword 清单」

路径：**模板消息 → 模板库 → 选用**（或在「我的模板」自建，自建需审核）

1. 选一个合适的模板（行业选「IT科技/互联网」或相近类目即可）
2. 选用后可增删 keyword，**建议保留 5～6 个**，与我们推送的字段对应
3. 记下两样东西：
   - **模板 ID**（形如 `xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx`）
   - **keyword 清单**：每个 keyword 对应哪个字段

推荐映射（后续要填到后台配置页）：

| keyword | 对应字段 |
|---------|---------|
| keyword1 | 呼号 |
| keyword2 | QTH |
| keyword3 | 设备 |
| keyword4 | 天馈 |
| keyword5 | 信号报告 |
| keyword6 | 时间 |

> 提示：微信模板的 keyword 数量通常有限（常见 5～6 个）。若只有 5 个，可把「设备」和「天馈」合并成一个 keyword（如「设备/天馈」），在后台映射里选其一即可。

### 步骤 4：配置服务器回调

路径：**设置与开发 → 基本配置 → 服务器配置**

| 项 | 填什么 |
|----|--------|
| 服务器地址(URL) | `https://你的域名/api/wechat/callback` |
| 令牌(Token) | 自定义一串字符（**必须与服务器 .env 的 `WECHAT_TOKEN` 完全一致**） |
| 消息加解密密钥 | 点「随机生成」即可 |
| 消息加解密方式 | 选 **明文模式**（当前实现按明文处理，最简单） |

> ⚠️ **顺序很重要**：必须**先把代码部署到服务器并启动**，再回来点「提交/启用」。
> 微信会立即向你填的 URL 发一次验证请求，若接口还不存在会提示「token 验证失败」。

### 步骤 5：配置网页授权域名

路径：**设置与开发 → 公众号设置 → 功能设置 → 网页授权域名**

1. 点击设置，页面会提示下载一个验证文件（形如 `MP_verify_xxxxxxxx.txt`）
2. 把该文件放到项目源码的 **`public/` 目录**下
3. **重新构建并部署**（本项目是 tar 覆盖部署，放好后重新打包部署即可）
4. 确认 `https://你的域名/MP_verify_xxxxxxxx.txt` 能在浏览器打开
5. 回到微信后台填入**纯域名**（如 `log.br4in.cn`，**不带 `https://`、不带路径**），保存

### 步骤 6：添加自定义菜单

路径：**内容与互动 → 自定义菜单**（旧版在「功能 → 自定义菜单」）

- 菜单名称：`绑定台网通知`
- 菜单类型：**跳转网页**
- 网页地址：`https://你的域名/wechat/bind`

> 无需填写微信授权链接，页面会自动发起静默授权（`snsapi_base`），用户无感知。

## 四、服务器侧配置（2 步）

### 步骤 7：配置 .env 并重启服务

在服务器项目根目录的 `.env` 追加（**不要加引号、不要有空格**）：

```env
WECHAT_APPID=wxXXXXXXXXXXXXXXXX
WECHAT_APPSECRET=XXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXX
WECHAT_TOKEN=与公众号后台填的Token完全一致
WECHAT_ENCODING_AES_KEY=公众号后台生成的密钥
WECHAT_TEMPLATE_ID=步骤3拿到的模板ID
MEMBER_ID_SALT=强随机字符串
```

| 变量 | 来源 | 说明 |
|------|------|------|
| `WECHAT_APPID` | 基本配置 → 公众号开发信息 | 公众号 AppID |
| `WECHAT_APPSECRET` | 同上 | AppSecret（只显示一次，注意保存） |
| `WECHAT_TOKEN` | 步骤 4 自填 | 必须与公众号后台一致 |
| `WECHAT_ENCODING_AES_KEY` | 步骤 4 生成 | 明文模式下暂不使用，但建议配上 |
| `WECHAT_TEMPLATE_ID` | 步骤 3 | 也可不配，改在后台配置页填写 |
| `MEMBER_ID_SALT` | 自行生成 | 生成命令：`openssl rand -base64 48` |

> 🔴 **`MEMBER_ID_SALT` 一旦启用绝对不可更改**。它是身份证后六位哈希的盐值，
> 更改后所有已导入的对照记录哈希全部失效，必须重新导入。
> 仅「绑定方式 = 身份证后六位」时需要，其他方式可不配。

改完重启服务（测试站：`pm2 restart test-log`；正式站：`pm2 restart radio-log`）。

### 步骤 8：后台参数设置

路径：**后台 → 微信推送 → 配置**

| 设置项 | 说明 |
|--------|------|
| 启用模板消息推送 | 总开关，**关闭时不会推送任何消息**（建议联调通过前保持关闭） |
| 站点/组织名称 | 显示在用户端绑定页（多中继台部署时可各自设置） |
| 模板 ID | 步骤 3 的模板 ID（若 .env 已配，此处可留空） |
| **模板字段映射** | 按模板实际 keyword 顺序，为每个 keyword 选择对应字段；不用的选「（不使用）」 |
| **绑定认证方式** | 三选一：`idcard` 身份证后六位 / `bindcode` 一次性绑定码 / `manual` 人工审核 |
| 绑定码长度、有效期 | 仅方式 B 生效；有效期填 0 表示长期有效 |
| 绑定页说明文案 | 展示在用户端绑定页顶部 |
| 允许用户自助解绑 | 关闭后只能由管理员在后台解绑 |
| 仅推送今天的场次 | 关闭后补录历史记录也会推送（可能造成打扰） |
| 同场次同呼号只推一次 | 关闭后主控每修改一次记录都会推送 |

## 五、三种绑定方式的使用

### 方式 A：身份证后六位（`idcard`）

**管理员准备**：后台 → 微信推送 → 会员对照表 → 上传 CSV/Excel
- 列顺序：**呼号，身份证后六位，姓名（可选）**
- 文件仅在浏览器本地解析，不上传服务器
- 身份证后六位在服务端加盐哈希后入库，**明文不落库**
- 同一呼号重复导入会覆盖更新

**用户流程**：公众号菜单 → 填呼号 + 身份证后六位 → 通过即生效

**安全设计**：
- 认证失败统一提示「信息不匹配」，**不提示是呼号不存在还是后六位错误**（防枚举）
- 失败限频：同一用户 10 分钟内最多 5 次尝试
- `MEMBER_ID_SALT` 不可变更

### 方式 B：一次性绑定码（`bindcode`）

**管理员准备**：后台 → 微信推送 → 绑定码 → 输入呼号（多个用逗号/换行分隔）→ 生成 → 复制清单发给用户

**用户流程**：公众号菜单 → 填呼号 + 绑定码 → 通过即生效，**码立即作废**

**特点**：
- 不涉及身份证，合规压力最小
- 码与呼号一一对应，泄露也需知道对应呼号才能绑定
- 支持有效期（默认 24 小时，可设 0 长期）与手动作废

### 方式 C：人工审核（`manual`）

**管理员准备**：后台 → 配置 → 认证方式选「人工审核」

**用户流程**：公众号菜单 → 填呼号提交 → 状态变为「待审核」

**管理员处理**：后台 → 微信推送 → 绑定管理 → 通过 / 拒绝
- 通过后状态变「已生效」，开始接收推送
- 拒绝后用户可修改呼号重新提交

> 三种方式均保证：**1 个微信只能绑 1 个呼号**（重复绑定会覆盖）；一个呼号可被多个微信绑定（如家人共用），推送时全部发送。

## 六、联调与验证（建议按顺序）

1. **检查密钥配置**：后台 → 配置页顶部，看 6 项是否全为绿色 ✔
2. **填模板 ID + keyword 映射**，保存
3. **测试推送**：在配置页底部填 openid（或已绑定用户的呼号）→ 点「发送测试消息」
   - 成功：页面提示消息 ID，微信应立即收到一条消息
   - 失败：页面显示错误码，对照第七节排查
4. **走一次真实绑定**：用所选方式完成一次绑定，后台「绑定管理」应能看到记录且状态为「已生效」
5. **提交真实记录**：主控台对**今天**的台网提交一条该呼号的记录
6. **确认收到回执**：用户微信应收到模板消息
7. **查看留痕**：后台 → 推送日志，可看到每次推送的状态、错误码、消息 ID

**验证检查清单**

| 检查点 | 期望 |
|--------|------|
| 配置页 6 项密钥 | 全绿 ✔ |
| 测试推送 | 微信收到测试消息 |
| 绑定管理 | 出现绑定记录，状态「已生效」 |
| 提交今日记录 | 该用户收到回执 |
| 推送日志 | 状态 success 且有 msgid |
| 补录历史记录 | 不推送（若开启了「仅推送今天的场次」） |
| 用户取关 | 绑定自动置为「已失效」，不再推送 |

## 七、常见问题排查

| 现象 | 可能原因 | 处理 |
|------|---------|------|
| 点「启用」提示 token 验证失败 | 代码未部署，或 `.env` 的 `WECHAT_TOKEN` 与公众号后台不一致 | 先部署再启用；核对 Token 完全一致（区分大小写） |
| H5 提示 `redirect_uri 参数错误` | 网页授权域名没配对 | 检查是否只填了域名（不带 https/路径），且验证文件已能公网访问 |
| H5 提示「无法发起微信授权」 | 未配 `WECHAT_APPID` | 配 `.env` 并重启服务 |
| 测试推送返回 `40001` | access_token 失效 | 系统已自动清缓存，直接重试一次即可 |
| 返回 `48001` | 模板消息权限未开通 | 回公众号后台开通模板消息功能 |
| 返回 `40037` | 模板 ID 错误 | 核对模板 ID 与 keyword 映射 |
| 返回 `43004` | 用户未关注公众号 | 让用户先关注再绑定 |
| 返回 `45009` | 超过日调用限额 | 次日再试或申请提额 |
| 日志显示成功但用户没收到 | 用户已取关或拒收该类消息 | 让用户重新关注；取关后系统会自动置为失效 |
| 提交记录后没推送 | 见下方逐项排查 | — |

**提交记录后没推送，按顺序排查：**
1. 后台「启用模板消息推送」开关是否打开
2. 该呼号的绑定状态是否为「已生效」（待审核/已拒绝/已失效都不推）
3. 台网场次时间是否为**今天**（若开启了「仅推送今天的场次」）
4. 同一场次同一呼号是否已推过（若开启了去重）
5. 后台 → 推送日志里是否有记录、状态与错误码是什么
6. 密钥是否配置齐全（AppID / AppSecret / 模板 ID）

## 八、安全与合规说明

- 身份证后六位**只存储 `sha256(后六位 + SALT)` 哈希**，SALT 保存在服务器 `.env`，明文不入库、不记日志
- 密钥（AppID / AppSecret / Token / AESKey / SALT）**只存 `.env`**，不入库、不通过任何接口返回
- 状态查询接口只返回「是否已配置」的布尔值，**不返回密钥明文**
- 后台绑定列表中的 openid **脱敏显示**（如 `oAbCdEfg****1234`）
- 授权跳转链接由服务端生成，并校验 `redirect_uri` 必须是本站地址（防开放重定向）
- 推送采用异步触发且内部捕获所有异常，**任何推送失败都不会影响记录提交主流程**
