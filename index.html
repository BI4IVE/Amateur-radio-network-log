济南黄河业余无线电台网主控日志系统 · 使用说明书

本说明书面向台网主控、管理员与部署运维人员，覆盖从「零开始部署」到「日常开台网、录入、导出、大屏、统计、升级」的全部操作流程。

Next.js 16React 19Node.js 24PostgreSQL 14+ MIT 协议当前版本 v1.5.20

典型一天的使用路径：预告倒计时 → 创建台网会话 → 呼号联想快速录入 → 多人实时协作 → 实况大屏投屏 → 导出 Excel 归档。

1系统概览与角色权限↑ 顶部

系统采用「管理员 + 主控」双角色模型。所有后台页面均受中间件保护，未登录会被重定向到 /login；非管理员访问管理员页面会被重定向回首页。

🌐 主页 / 主控台 /创建台网会话、录入记录、导出 Excel，是主控每天唯一需要停留的页面。
📡 实况大屏 /live实时滚动在网呼号与最新记录，可投屏电视 / 拼接屏，支持电脑版与竖屏手机版。
🔍 呼号查询 /query查询某呼号近一年的参与记录与参与次数，可生成参与证书。
⚙️ 管理后台 /admin三大分组：运营中心 / 数据与日志 / 系统管理，共 12 个功能页面。
🔐 登录 /login用户名不区分大小写，登录态保存在 httpOnly Cookie，有效期 7 天。
🔄 实时协作基于 SSE（Server-Sent Events），多主控同时录入即时互见，30 秒心跳保活。

3部署安装（四种方式）↑ 顶部

方式适用场景难度
宝塔面板国内服务器可视化运维（推荐）⭐⭐
传统 Linux纯命令行 VPS / 云主机⭐⭐⭐
Docker容器化 / 一键迁移⭐⭐
Coze Coding已弃用，仅历史参考—

方式一：宝塔面板（推荐）

  1. 安装 Nginx、Node.js 24、PostgreSQL 14、PM2 四件套。
  2. 「数据库」→ 添加数据库，名称如 radio_network_log，记下用户名密码。
  3. 「文件」→ 在 /www/wwwroot/ 建项目目录并上传 / 解压源码。
  4. 终端进入目录执行 pnpm install。
  5. 创建 .env（见「环境变量」一节）。注意：不要用 cp .env.example .env，非交互终端会被覆盖确认打断，建议用 cat > .env 强制写入。
  6. 执行 pnpm db:push 建表。
  7. 执行 pnpm build 构建产物。
  8. PM2 启动：pm2 start npm --name "radio-log" -- start，然后 pm2 save 与 pm2 startup。
  9. 「网站」→ 添加站点 → 纯静态 → 配置文件改为下面的反向代理。
  10. 申请 Let's Encrypt SSL 并开启强制 HTTPS。
  11. 浏览器访问域名，用 ADMIN + ADMIN_INIT_PASSWORD 登录。
宝塔避坑：PM2 与宝塔「Node 项目」二选一

两者都会监听同一端口导致 EADDRINUSE。推荐只用 PM2（本项目）或只用宝塔 Node 项目托管，不要并存。宝塔 Node 项目底层不是全局 pm2，pm2 list 看不到它。

Nginx 反向代理（务必带 SSE 与真实 IP 头）

server {
    listen 80;
    server_name your-domain.com;

    location / {
        proxy_pass http://127.0.0.1:5000;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection 'upgrade';
        proxy_set_header Host $host;
        proxy_cache_bypass $http_upgrade;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_buffering off;
    }
}
为什么必须加 X-Real-IP 与 proxy_buffering off

登录限流按 IP 统计，缺失会导致所有人被当成同一个 IP 而触发「登录尝试次数过多」；关闭缓冲才能保证 SSE 实时推送不被积压。

cd /var/www/radio-log

首次初始化管理员

管理员账号由系统自动初始化：用户名固定为 ADMIN（大写），密码取自环境变量 ADMIN_INIT_PASSWORD。

安全提醒

自 v1.5.1 起 /api/users 创建接口要求管理员权限，不能再用 curl 匿名创建管理员；/api/reset-admin 已永久删除。请配置好 ADMIN_INIT_PASSWORD 后访问首页完成初始化，并尽快在「用户管理」中修改密码。

4环境变量（.env）↑ 顶部

变量必填说明
DATABASE_URL✔如 postgresql://user:pass@localhost:5432/radio_network_log
JWT_SECRET✔JWT 签名密钥。v1.5.13 起缺失将直接拒绝启动。生成：openssl rand -base64 48
ADMIN_INIT_PASSWORD✔初始化 ADMIN 账号的初始密码，同时作为 /api/init 的校验令牌
PORT推荐服务监听端口，默认 5000，需与 Nginx 反代一致
NODE_ENV推荐生产环境设为 production
FORCE_SECURE_COOKIE可选站点为 HTTPS 时设为 true，Cookie 才会带 Secure 属性
UPGRADE_MANIFEST_URL可选在线版本检测清单地址，默认指向 GitHub raw 的 version/upgrade-manifest.json

完整示例

DATABASE_URL=postgresql://radio_user:your_password@localhost:5432/radio_network_log
PORT=5000
NODE_ENV=production
JWT_SECRET=用 openssl rand -base64 48 生成的随机强密钥
ADMIN_INIT_PASSWORD=你的初始管理员密码
FORCE_SECURE_COOKIE=true
UPGRADE_MANIFEST_URL=https://raw.githubusercontent.com/BI4IVE/Amateur-radio-network-log/main/version/upgrade-manifest.json
服务器 .env 行尾带 CR

用脚本 grep / cut 取值时记得去除回车，否则密码会多出不可见字符导致连不上库。

5登录与账号↑ 顶部

  1. 浏览器访问站点根路径，未登录会自动跳转到 /login。
  2. 输入用户名与密码，点击「登录」。
  3. 登录成功写入本地用户信息并跳转首页 /。
  4. 退出登录请点右上角「退出」，服务端清除 httpOnly Cookie 后回到登录页。
用户名大小写不敏感（服务端用 SQL LOWER() 匹配），bi4ive 与 BI4IVE 等价。呼号输入则自动转大写。
登录态有效期Cookie 名 token，httpOnly + SameSite=Lax，有效期 7 天。
IP 限流同一 IP 每分钟最多 10 次登录尝试，超出返回「登录尝试次数过多，请稍后再试」。
账号锁定同一账号 15 分钟内连续失败 5 次，锁定 15 分钟：「该账号已被临时锁定，请 15 分钟后再试」。

修改密码（管理员）

「系统管理 → 用户管理」中找到目标用户 →「修改密码」，输入新密码保存即可。普通主控如需改密，请联系管理员。

口令存储

系统使用 bcrypt 哈希存储。若库中存有早期明文密码，该用户下次登录成功时会自动升级为哈希。

首页 / 自上而下分为：页头按钮区 → 台网预告倒计时 → 台网主控人员信息卡 → （创建会话后）左「记录录入」/ 右「记录列表」。

台网预告倒计时

卡片自动显示最近一条「未来台网预告」：主题、时间、主控、天 / 时 / 分 / 秒倒计时，每秒刷新、每 30 秒重新拉取。倒计时归零后显示「台网时间已到」，管理员会额外看到一个「开始台网」按钮，点击后自动跳转实况大屏。

预告由管理员在「运营中心 → 台网预告」创建（主题 + 时间 + 主控），新建后首页与大屏自动生效。

创建台网会话

  1. 在「台网主控人员信息」卡填写：主控人员（管理员可从下拉选择任意主控；主控角色自动锁定为自己）、台网时间（默认当前北京时间）、主呼号、设备、天线、QTH。
  2. 「使用数据库中的信息」开关默认开启：选择主控后自动回填其设备 / 天线 / QTH。
  3. 点击「创建新会话」，弹出「新台网会话已创建」即成功，右侧出现「会话ID」。
  4. 会话创建后，页面下半部分才会出现录入表单与记录列表。
🕐 时区所有时间均为北京时间（UTC+8）：前端按北京时区显示，入库时转换为 UTC 存储。
📅 一天一场同一北京日期只允许一场台网。重复创建会提示「今天已存在台网记录，无法重复录入」，请到「台网历史管理」修改已有记录。

加入已有会话

点击「查看当前台网」，弹出活跃会话列表（系统已自动过滤过期会话），显示主控、台网时间、QTH、设备、天线，点「加入会话」即可加入协作。列表为空时提示「当前没有活跃的台网会话」。

没有「结束会话」按钮

系统未提供手动结束入口。会话会随可编辑时限自动过期；如需切换，加入另一个会话或直接退出登录即可。

标准录入流程

  1. 光标定位到呼号框（提交后系统会自动把焦点送回这里，方便连续录入）。
  2. 输入呼号前两位，出现联想列表，用 ↑↓ 选择、Enter 确认。
  3. 选中历史参与者后，QTH / 设备 / 天馈 / 功率 / 信号 / 报告 / 备注会自动回填（受「使用数据库中的信息」开关控制）。
  4. 按需微调信号与报告，按 Ctrl+Enter 或点击「添加记录 (Ctrl+Enter)」。
  5. 提示「记录已添加并更新参与人员库」（或「记录已添加并创建新参与人员」），右侧列表立即出现新记录。
参与人员库自动维护

每次录入都会 upsert 参与人员：已存在则更新设备 / QTH 等资料，不存在则新建。这就是呼号联想越用越好用的原因。

必填校验提示原文

缺少必填项时依次弹出：请输入呼号、请输入QTH、请输入天馈、请输入功率、请输入信号。未创建会话就录入会提示 请先创建台网会话。

8实时协作 · 编辑删除 · 导出↑ 顶部

多主控实时协作（SSE）

进入会话后浏览器建立 /api/sse/session/{会话ID}/subscribe 长连接，服务端每 30 秒发送心跳保活。任一主控新增 / 修改 / 删除记录，其他主控页面无需刷新即时同步（事件类型：record_added、record_updated、record_deleted）。

实时同步失效排查

多为反向代理缓冲了 SSE。请确认 Nginx 配置中含有 proxy_buffering off; 与 proxy_http_version 1.1;。

可编辑时限

后台「页面配置」中的 session_edit_hours 控制台网可编辑时长，默认 6 小时，填 0 表示不限制。前端每 60 秒复检一次，过期后记录列表顶部出现红色提示条：

会话已超过可编辑时限，无法添加、更新或删除记录

管理员不受时限限制，可随时在「数据与日志 → 台网历史管理」中补录或修改任意记录。

编辑与删除

操作管理员主控
编辑按钮显示显示（限自己主控的会话 + 未过期）
删除按钮显示不显示

删除为软删除（写入 deleted_at 并记审计日志），确认框文案为「确定要删除这条记录吗？」，成功提示「记录已删除」。误删可到「数据与日志 → 回收站/审计」一键恢复。

越权操作提示：您没有权限操作此台网记录、您没有权限编辑此记录。

9实况大屏 /live↑ 顶部

用于活动现场投屏，实时展示在网呼号、最新记录、当前主控参数与模拟频谱。

五种显示模式

模式URL适用
电脑版/live 或 /live?screen=default横屏电视 / 拼接屏
简洁版/live?screen=minimal低干扰投屏
街机版/live?screen=arcade科技感展示
默认大屏 M/live?screen=defaultM竖屏（手机 / 竖屏一体机）
手机版竖屏/live?screen=portrait手机观看

切换方式：电脑版三种模式用右上角下拉选择；竖屏模式在页面底部有「默认大屏M / 手机版 / 电脑版」切换条。切换只改 URL 参数，不会刷新页面，可直接把对应 URL 存为大屏书签。

页面内容

  • 顶栏：大屏名称、接收 / 发射频率、亚音、本地时钟。
  • 当前主控面板：最新参与者呼号、QTH / 设备 / 天馈 / 功率、R·S·T 信号环与信号质量条。
  • 台网总人数：去重呼号数、记录数、进度条（按 60 满格）。
  • 最近记录列表：按时间倒序，超出高度自动滚动。
  • 模拟频谱 + 日期 ticker：动态装饰效果。

数据每 3 秒轮询刷新一次（大屏不依赖 SSE，兼容性更好）。暂无记录时显示「等待主控录入记录…」；连接异常显示「连接服务器失败」。

对外开放与 QTH 脱敏

screen_public未登录访客看到已登录
false（默认）玻璃拟态遮罩：「大屏未到公开时间 / 当前大屏仅为内部使用…」+「登录查看」「返回站点首页」正常显示，QTH 完整
true正常显示，但 QTH 仅保留前 4 个字正常显示，QTH 完整

该开关在「系统管理 → 页面配置」中修改（screen_public），另有 screen_title、screen_rx_freq、screen_tx_freq、screen_tone 可自定义大屏抬头参数。

登录态判定

大屏通过浏览器本地存储判断登录，请在用于投屏的浏览器上先登录一次；换浏览器 / 无痕模式会被视为未登录。

投屏建议

  • 电视 / 拼接屏（横屏）：/live?screen=default，浏览器 F11 全屏。
  • 立式广告机 / 手机上墙：/live?screen=portrait。
  • 长时间投屏建议关闭屏幕休眠，并可用浏览器自动刷新插件做兜底。

10呼号查询 /query↑ 顶部

  1. 点击页头「呼号查询」，或直接访问 /query。
  2. 输入呼号（自动转大写），点击查询。
  3. 结果展示：呼号、1 年内参与总次数、每次参与的台网时间与当值主控，按时间倒序，每页 20 条。
  4. 支持 URL 直达：/query?callsign=BI4IVE，方便分享给台友。
统计口径

为精确匹配（不做模糊查询），统计区间为最近 1 年，以台网时间 session_time 为准并排除已删除记录。无结果时显示「暂无参与记录」。

查询页还支持生成 / 保存 / 打印参与证书，签发单位与机构由后台配置 cert_sign_unit、cert_sign_org 控制。

13版本升级与回滚↑ 顶部

一、纯代码更新（最常见）

cd /项目目录
git pull origin main
pnpm install
pnpm build
pm2 restart radio-log

Docker 环境用 docker-compose up -d --build。完成后登录后台 →「系统管理 → 版本更新」→「立即检测」，系统会自动把数据库版本号回写为最新版。

提示

纯代码更新不需要执行 pnpm db:push。

二、含数据库表结构变更

  1. 先备份：pg_dump -U 用户 -h localhost -d radio_network_log -F c -f radio_log_$(date +%Y%m%d).dump
  2. 拉代码、装依赖、构建（同上）。
  3. 执行迁移：pnpm db:push（Drizzle 按 schema 自动增量建表 / 加列，不删数据）。
  4. 重启服务，后台点一次版本检测同步版本号。
如何判断是否需要迁移

查看该版本更新日志是否标注「涉及表结构变更」，或对比 src/storage/database/shared/schema.ts 是否有新增表 / 字段。历史案例：v1.5.12（新增 audit_logs 表 + deleted_at 字段）、v1.5.13（一天一场唯一索引）。

三、三处版本源必须一致

#位置字段说明
1version/upgrade-manifest.jsonlatest远程最新版（检测基准）
2src/lib/version.tsCODE_VERSION当前部署代码版本
3数据库 page_configs（key=version）value线上运行版本，部署后由检测自动同步

四、回滚

git log --oneline -5
git checkout <旧提交哈希>
pnpm install && pnpm build && pm2 restart radio-log
回滚不回退表结构

若之前执行过 db:push，回滚代码后表结构不会自动回退，需用升级前的 pg_dump 备份用 pg_restore 恢复。所以表变更前备份极其重要。

14故障排查 FAQ↑ 顶部

数据库连接失败

  • 检查 PostgreSQL 是否启动、库是否已创建、用户名密码是否正确。
  • 检查 .env 的 DATABASE_URL；若值由脚本 grep 取得，注意去除行尾回车。
  • 宝塔环境注意 permission denied for schema public (42501)，需 GRANT ALL ON SCHEMA public。

服务启动即退出，提示 JWT_SECRET 相关

v1.5.13 起 JWT_SECRET 为强制项，缺失会拒绝启动（有意设计，避免弱密钥）。执行 echo "JWT_SECRET=$(openssl rand -base64 48)" >> .env 后重启。

端口 5000 被占用

lsof -i:5000
kill -9 <PID>

或用 pm2 delete 释放端口后再启动，避免与宝塔 Node 项目抢端口。

多主控录入不同步

  • 确认 Nginx 含 proxy_buffering off; 与 proxy_http_version 1.1;。
  • 确认中间 CDN / WAF 没有缓冲 text/event-stream。
  • SSE 端点为 /api/sse/session/{id}/subscribe，30 秒心跳，需登录。

会话无法编辑 / 提示已过期

默认 6 小时可编辑时限。管理员可在「页面配置」把 session_edit_hours 调大或设为 0（不限制）；主控请改用管理员账号在「台网历史管理」中补录。

创建会话提示「今天已存在台网记录」

同一北京日期只允许一场台网。请到「数据与日志 → 台网历史管理」修改当天已有记录，或先删除（回收站可恢复）再重建。

后台显示「v1.1.0 兜底默认值（数据库读取失败）」

全新库 page_configs 为空所致。用管理员 token 依次调用 POST /api/admin/migrate/page-configs 与 POST /api/admin/upgrade/check 即可同步为真实版本。

登录提示「尝试次数过多」/「账号已被锁定」

IP 限流 10 次 / 分钟；账号连续失败 5 次锁定 15 分钟。请确认 Nginx 传递了 X-Real-IP，避免所有人被算作同一 IP。

Excel 导入无反应或全部失败

  • 仅支持 .xlsx / .xls / .csv。
  • 设备库导入请先「下载导入模板」，按模板列名填写。
  • 导入结果以「总计 N 条，成功 M 条，失败 K 条」形式提示，失败条数不为 0 时请核对必填列。

实况大屏显示遮罩「大屏未到公开时间」

说明 screen_public=false 且当前浏览器未登录。在该浏览器登录一次即可；或由管理员在「页面配置」把 screen_public 改为 true 对外开放（此时未登录访客看到的 QTH 仅显示前 4 个字）。

页面改了没生效

点页头「清理缓存」（清除本地存储 + 注销 Service Worker + 强制刷新）。该操作不会删除任何服务器数据。

D. 安全与运维建议

  • JWT_SECRET 与 ADMIN_INIT_PASSWORD 必须使用随机强值，部署后立即修改默认管理员密码。
  • 启用 HTTPS 后把 FORCE_SECURE_COOKIE 设为 true。
  • 数据库定期 pg_dump 备份；执行表结构迁移前必备份。
  • .env 不要提交进仓库；.dockerignore 排除 .env、.git、node_modules。
